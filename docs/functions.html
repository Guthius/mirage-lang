Functions

Declaring, calling, and passing functions in Mirage.

Basic Function Declarations

fn add(a: i32, b: i32) -> i32 {
    return a + b
}

# No return value (void)
fn greet(name: *u8) {
    printf("Hello, %s!\n", name)
}

Mutable Parameters

Function parameters are immutable by default. Declare a parameter mut to make it mutable inside the function:

fn countdown(mut n: i32) {
    while n > 0 {
        printf("%d\n", n--)
    }
}
Note
Making a parameter mut does not affect callers — Mirage passes by value. To modify the caller's variable, pass a pointer.

Multi-Return Functions

Functions can return multiple values. The return types are listed in parentheses after ->. Callers use group declarations to capture them. 

fn divmod(a: i32, b: i32) -> (i32, i32) {
    return a / b, a % b
}

mut q, r := divmod(17, 5)   # q=3, r=2

Discarding Return Values

Use _ to discard one or more return values:

mut q, _ := divmod(17, 5)   # only keep quotient

Fallible Functions (Typed Errors)

A function is fallible when its last return type is error(T) (a single error type) or error(A | B | C) (a union of error types). T, A, B, ... are ordinary enum(i32) or tagged-union (union(enum)) types you declare yourself — there is no built-in error type or convention-based error code. 

type MathError = enum(i32) {
    DivideByZero
}

fn divide(a: i32, b: i32) -> (i32, error(MathError)) {
    if b == 0 { return_err .DivideByZero }
    return_ok a / b
}

# Must capture the error, or propagate with try
mut result, err := divide(10, 2)
if err { /* handle failure */ }

# Or propagate with try (enclosing fn must return a compatible error(...))
const val: i32 = try divide(10, 2)

See Error Handling for the full error(...) system: return_ok/return_err, try, and typestate checking.

Native Variadic Parameters

A function's final parameter may be declared name: ...T to accept any number of trailing arguments of type T. Inside the function body, name is an ordinary []T slice: 

fn sum(base: i32, nums: ...i32) -> i32 {
    mut total := base
    for n in nums {
        total += n
    }
    return total
}

sum(10)             # zero variadic args — nums is an empty slice
sum(10, 1, 2, 3)   # nums is []i32{1, 2, 3}

# An existing slice can be forwarded directly with '...' spread
const values: []i32 = {1, 2, 3}
sum(0, values...)
Not the same as ext fn varargs
Native variadics are fully type-checked against T (including implicit tagged-union coercion) — unlike an ext fn's untyped C .... A function with a native variadic parameter cannot have its address taken as a function pointer.

Visibility: pub

By default, functions are module-private. Add pub to make them accessible from other modules: 

pub fn compute(x: i32) -> i32 {
    return x * 2
}

# Private — only callable within this module
fn helper(x: i32) -> i32 {
    return x + 1
}

Extern Functions

Use ext fn to declare external C functions. The declaration provides the Mirage-visible type signature; the linker resolves the actual symbol. 

# C standard library declarations
ext fn puts(s: *u8) -> i32
ext fn malloc(size: usize) -> anyptr
ext fn free(ptr: anyptr)
ext fn memcpy(dest: anyptr, src: anyptr, n: usize) -> anyptr
Note
ext fn parameters and return types cannot be structs, arrays, slices, or unions — only scalars, pointers, and function pointer types.

Variadic Extern Functions

Add ... at the end of the parameter list to declare a variadic extern function. At least one named parameter must come before .... 

ext fn printf(fmt: *u8, ...) -> i32
ext fn snprintf(buf: *u8, n: u64, fmt: *u8, ...) -> i32

printf("%d %f\n", 42, 3.14)
Variadic Argument Types
Variadic arguments must be at least 32 bits wide and match C's default argument promotion rules. Valid types: i32, u32, i64, u64, usize, f64, typed pointers, anyptr. Narrower types (e.g. f32, u8) must be explicitly cast first. error(...) values cannot be passed as C-style variadic arguments.

Entry Points

The root module must define exactly one of:

pub fn main() { /* ... */ }                             # exits with code 0
pub fn main() -> i32 { return 0 }                         # returns exit code
pub fn main() -> error(AppError) { return_ok }        # Ok exits 0, Failed exits 1

For freestanding builds (--freestanding), define fn _start() instead. The pub modifier is not required for _start.

Function Pointers

Functions are first-class values. They can be stored in variables, passed to functions, and stored in structs.

Storing and Calling

fn square(x: i32) -> i32 { return x * x }

mut fp: fn(i32) -> i32 = square
const r: i32 = fp(9)   # 81

Higher-Order Functions

fn apply(op: fn(i32, i32) -> i32, x: i32, y: i32) -> i32 {
    return op(x, y)
}

const sum := apply(add, 3, 4)   # 7

Variadic Function Pointer

ext fn printf(fmt: *u8, ...) -> i32

mut vfp: fn(*u8, ...) -> i32 = printf
vfp("%d\n", 42)

Multi-Return Function Pointer

fn divide(a: i32, b: i32) -> (i32, error(MathError)) {
    if b == 0 { return_err .DivideByZero }
    return_ok a / b
}

mut fp: fn(i32, i32) -> (i32, error(MathError)) = divide
mut val, err := fp(10, 2)

# try also works through fn ptrs
const v: i32 = try fp(8, 2)

Macros

Macros are expression-level compile-time substitutions. They look like function calls but expand to an inline expression. 

macro max(a: i32, b: i32) -> a > b ? a : b
macro align_up(n: usize) -> (n + (alignment - 1)) & ~(alignment - 1)

const m := max(3, 7)        # expands to: 3 > 7 ? 3 : 7 → 7
const alignment: usize = 16
const size: usize = 20
const aligned := align_up(size)   # (20 + 15) & ~15 = 32
Macro bodies resolve names at their own declaration site
A macro's body is checked once, where the macro itself is declared — alignment above must be a name visible there (a module-level const/mut or another macro/function), not something local to whichever function happens to call the macro.

Macros can be exported with pub:

pub macro min(a: i32, b: i32) -> a < b ? a : b

An optional : ReturnType annotation goes between the parameter list and ->. It's required whenever the body can't infer its own type without context — a struct-literal body, for instance, needs an expected type the same way a const/mut initializer does: 

type Vector = struct {
    element_size: usize
}

pub macro new_vector(element_size: usize): Vector -> {.element_size = element_size}
Macros vs Functions
Macros are syntactic substitution — they cannot be stored as function pointers and cannot recurse. They are ideal for small, performance-critical inline expressions.
