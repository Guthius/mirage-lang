Getting Started

Build Mirage from source and write your first program.

Building the Compiler

Mirage requires LLVM and a C++ compiler. The project uses just as its build tool.

# Clone and build
git clone <repo-url>
cd Mirage
just build

The compiler binary is produced at ./build/mirage.

Modules are directories
Mirage source files use the .mir extension, but the compiler always takes a directory as its input, never a single file. Every .mir file directly inside that directory is merged into one module — so a module can be split across several files if that's convenient, but it doesn't have to be.

Command-Line Usage

mirage <action> <module-dir> [options]
ActionDescription
buildCompile a module directory to an executable
runCompile the module and immediately run the resulting executable
OptionDescription
-o, --output <file>Output file name (default: a.out)
-l <lib>Link an additional library, e.g. -l m for libm (repeatable)
--emit-irPrint the generated LLVM IR to stdout instead of producing a binary
--freestandingCompile without the standard hosted entry point; the module must supply fn _start()
--helpShow usage information
# Compile the module in ./hello to ./hello_app
./build/mirage build hello -o hello_app

# Compile and run in one step
./build/mirage run hello

# Inspect the generated LLVM IR instead of compiling
./build/mirage build hello --emit-ir

# Link against an extra library
./build/mirage build hello -o hello_app -l m

# Freestanding build (no libc, custom _start)
./build/mirage build kernel --freestanding -o kernel.bin

Hello, World

Mirage does not have a built-in print function. Instead, it calls the C standard library's printf via an ext fn declaration — typical for Mirage programs that run in a hosted environment. 

# hello/main.mir

ext fn printf(fmt: *u8, ...) -> i32

pub fn main() {
    printf("Hello, World!\n")
}
./build/mirage run hello
# Hello, World!

Entry Points

The root module must define a pub fn main using one of three signatures: 

# No return value — exits with code 0
pub fn main() {
    # ...
}

# Returns an explicit exit code
pub fn main() -> i32 {
    return 0
}

# Returns a typed error — Ok exits 0, Failed exits 1
type AppError = enum(i32) { SetupFailed }

pub fn main() -> error(AppError) {
    return_ok
}

See Error Handling for the full error(...) system. For freestanding builds (--freestanding), define fn _start() instead — pub is not required for _start.

Basic Program Walkthrough

Let's walk through a small but complete Mirage program that shows variables, conditionals, loops, and C interop. 

# fizzbuzz/main.mir

ext fn printf(fmt: *u8, ...) -> i32

fn fizzbuzz(n: i32) {
    mut i: i32 = 1
    while i <= n {
        if i % 15 == 0 {
            printf("FizzBuzz\n")
        } else if i % 3 == 0 {
            printf("Fizz\n")
        } else if i % 5 == 0 {
            printf("Buzz\n")
        } else {
            printf("%d\n", i)
        }
        i++
    }
}

pub fn main() {
    fizzbuzz(20)
}

Key points in this example:

  • ext fn printf — declares the C printf function as a variadic extern.
  • mut i: i32 = 1 — declares a mutable variable with an explicit type.
  • while i <= n { ... } — a condition-checked loop (Mirage also has for ... in, see Control Flow).
  • i++ — post-increment expression.
  • i % 15 — modulo operator.

Variables and Constants

# Mutable variable — type inferred
mut x := 42

# Mutable variable — explicit type
mut y: f64 = 3.14

# Immutable constant — cannot be reassigned
const limit := 100

# Default initialization — struct/array fields zeroed
mut buf: [256]u8

# Uninitialized — storage allocated, no write
mut tmp: i32 = undefined
tmp = 99

Type Inference

Mirage infers the type of a variable from its initializer when no annotation is given. The := syntax means "infer the type": 

const a := 10         # a: i32
mut   b := 3.14       # b: f64
const c := true        # c: bool
const s := "hello"    # s: *u8
Note
Mirage does not implicitly promote or coerce numeric types. To mix types in arithmetic, use cast(expr, TargetType).
