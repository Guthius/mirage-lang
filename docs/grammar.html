Grammar Reference

Complete EBNF grammar derived from the Mirage parser (src/compiler/ast.cpp). Terminals appear in 'single quotes' or as UPPERCASE token classes. [...] = optional, {...} = zero or more, | = alternative.

Top-Level Structure

program       ::= { declaration } EOF

declaration   ::= [ attribute ] [ 'pub' ] fn_decl   -- attribute: only legal here, see below
               | [ 'pub' ] ext_fn_decl
               | [ 'pub' ] type_decl
               | [ 'pub' ] var_decl
               | [ 'pub' ] macro_decl
               | impl_decl           -- impl cannot be pub
               | link_decl           -- cannot be pub
               | diagnostic_decl     -- cannot be pub
               | when_decl           -- cannot be pub

Declarations

Function Declaration

fn_decl       ::= [ attribute ] 'fn' IDENT '(' [ param { ',' param } ] ')' [ return_types ] stmt

param         ::= [ 'mut' ] IDENT ':' type
               | IDENT ':' '...' type   -- native variadic; must be the last parameter

return_types  ::= '->' ret_item
               | '->' '(' ret_item { ',' ret_item } ')'

ret_item      ::= [ IDENT ':' ] [ '?' ] type   -- the 'IDENT :' name is optional and purely
                                                  cosmetic (self-documenting); no functional effect.
                                                  '?' marks an ignorable error and is legal ONLY on
                                                  the last ret_item

pub, if present, comes after the attribute: @naked pub fn f() { ... }, never pub @naked fn f() { ... }.

A return type (single, or per-entry within a multi-return list) may optionally be named — -> (index: usize, found: bool) — purely to make the signature self-documenting (e.g. in editor hover). It has no functional effect: it does not create an implicit binding, and return still requires explicit values, exactly as with unnamed return types. A leading ? on the last return type marks an ignorable error (-> (anyptr, ?Allocator_Error)) — the only position where the parser accepts a ? in type position at all; see Ignorable Errors. Naming is independent per entry, so a multi-return list may mix named and unnamed entries.

Declaration Attributes

attribute     ::= '@' IDENT                              -- single, no arguments
               | '@' IDENT '(' expr { ',' expr } ')'    -- single, with arguments
               | '@' '(' IDENT { ',' IDENT } ')'        -- grouped, no arguments

-- only one attribute clause may precede a declaration; '@naked @no_return' (two
-- separate clauses) is a parse error, use the grouped form '@(naked, no_return)'
-- instead. A grouped member never takes its own argument list —
-- '@(section(".text"))' is a parse error; only the ungrouped '@name(args)' form
-- takes arguments. Known names: no_return, naked, always_inline, section, init
-- (see comptime-config.html's sibling page, attributes.html, for full semantics).
-- Currently legal only immediately before 'fn' — no other declaration kind.

Extern Function Declaration

ext_fn_decl   ::= ext_kw 'fn' IDENT '(' [ ext_params ] ')' [ '->' type ]

ext_kw        ::= 'ext'     -- parsed as an identifier, not a keyword token

ext_params    ::= ext_param { ',' ext_param } [ ',' '...' ]
               | '...'      -- error: requires at least one named param first

ext_param     ::= IDENT ':' type

Type Declaration

type_decl     ::= 'type' IDENT '=' type

Variable / Constant Declaration

var_decl      ::= ( 'mut' | 'const' ) IDENT
                  ( ':' type [ '=' expr ]
                  | ':=' expr )

-- 'const' requires an initializer
-- a top-level 'const' initializer may be import(...)

Macro Declaration

macro_decl    ::= 'macro' IDENT '(' [ macro_param { ',' macro_param } ] ')' [ ':' type ] '->' expr

macro_param   ::= IDENT ':' type

-- the optional ': type' names the macro's result type explicitly;
-- required when the body can't infer its own type without context (e.g. a struct literal)

Impl Block

impl_decl     ::= 'impl' named_type '{' { method_decl } '}'                    -- bare impl
               | 'impl' named_type 'for' named_type '{' { method_decl } '}'  -- trait impl

method_decl   ::= [ 'pub' ] 'fn' IDENT
                  '(' ( 'self' | 'mut' 'self' )
                      { ',' [ 'mut' ] IDENT ':' type }
                  ')'
                  [ return_types ]
                  stmt

-- in the trait-impl form, 'pub' on an individual method_decl is rejected —
-- the trait's own visibility governs which methods are externally callable

Link Declaration

link_decl     ::= '#link' '(' link_category ',' expr ')'

link_category ::= 'lib' | 'system' | 'flag'

-- '#' is a sigil, not part of an identifier; 'link' (like 'ext' above) is parsed
-- as a plain identifier immediately following it, not a reserved keyword. A
-- module-scope linker directive: 'lib' links a library file (path relative to the
-- current module file's directory), 'system' links a system library by name,
-- 'flag' passes a raw linker flag verbatim. 'data' must be a compile-time
-- constant '[]u8' expression — the when_expr form is legal here. Legal at module
-- scope or inside a module-scope 'when' block; a sema error everywhere else.

Diagnostic Declaration

diagnostic_decl ::= diagnostic_kw '(' expr ')'

diagnostic_kw   ::= 'error' | 'warn'   -- '#error'/'#warn'; 'error' is the KwError
                                           keyword, 'warn' a plain identifier

-- '#' is a sigil, not part of the keyword/identifier that follows it. A
-- compile-time diagnostic directive: '#error' emits a sema error, '#warn' a
-- sema warning, at the directive's location. 'expr' must be a compile-time
-- constant '[]u8' expression, exactly like link_decl's 'data' above. Legal at
-- module scope or inside a module-scope 'when' block; a sema error everywhere
-- else — mirrors link_decl exactly.

When Declaration

when_decl     ::= 'when' expr block_decl [ 'else' ( when_decl | block_decl ) ]

block_decl    ::= '{' { declaration } '}'

-- a compile-time conditional declaration block; 'expr' must be a compile-time
-- constant expression. Parses any declaration kind inside block_decl; sema
-- restricts the permitted kinds to '#link', '#error', '#warn', 'const' with
-- '#option'/'#env', 'type', and 'ext fn' — see the Compile-Time Configuration page.

Types

type          ::= '*' type                              -- pointer
               | '[' ']' type                          -- slice
               | '[' expr ']' type                     -- array
               | '[' '?' ']' type                       -- array, size inferred from initializer
               | struct_type
               | enum_type
               | union_type
               | trait_type
               | error_type
               | bitset_type
               | fn_type
               | named_type
               | builtin_type

struct_type   ::= 'struct' [ '(' 'packed' ')' ] '{'
                    { IDENT ':' type [ '=' expr ] }   -- no separator required between fields
                  '}'

enum_type     ::= 'enum' [ '(' type ')' ] '{'
                    { IDENT [ '=' expr ] }             -- no separator required between variants
                  '}'

union_type    ::= 'union' '{'                          -- untagged
                    { IDENT ':' type }
                  '}'
               | 'union' '(' 'enum' ')' '{'            -- tagged
                    { IDENT [ ':' type ] }
                  '}'

trait_type    ::= 'trait' '{' { trait_method_decl } '}'
               | 'trait' '(' named_type { ',' named_type } ')' [ '{' { trait_method_decl } '}' ]
                  -- a trait handle type; must declare at least one method (empty trait{} is an
                  -- error). The second form COMPOSES one or more other traits (each a
                  -- named_type, no generic_args — traits are never generic); the brace body
                  -- is optional when a composition list is present, but if written must be
                  -- non-empty, same as the bare form. A composed-list entry that doesn't
                  -- resolve to a trait, a duplicate entry, or a composition cycle are sema
                  -- errors, not parse errors — see the Traits page's "Trait Composition"
                  -- section for flattening/collision/cycle semantics.

trait_method_decl ::= 'fn' IDENT
                      '(' ( 'self' | 'mut' 'self' ) { ',' IDENT ':' type } ')'
                      [ return_types ]
                  -- signature only, no body; no 'pub'; no native-variadic ('...T') param;
                  -- non-self params do NOT accept a 'mut' prefix (unlike method_decl)

error_type    ::= 'error' '(' named_type { '|' named_type } ')'
                  -- named_type must be an enum(i32) or union(enum) type; duplicate members are an error

bitset_type   ::= 'bitset' '(' named_type [ ',' builtin_type ] ')'
                  -- first arg must resolve to an enum type (a plain 'enum {}' with no backing
                  -- type is fine — defaults to i32, like any enum); second arg, if present,
                  -- must be u8/u16/u32/u64 (defaults to u32). Always a distinct type, never
                  -- an alias — see the Structs & Types page's "Bitsets" section.

fn_type       ::= 'fn' '(' [ fn_type_params ] ')'
                    [ '->' fn_ret_item | '->' '(' fn_ret_item { ',' fn_ret_item } ')' ]

fn_ret_item   ::= [ '?' ] type   -- '?' legal only on the last item

fn_type_params ::= fn_type_param { ',' fn_type_param } [ ',' '...' ]
                | '...'

fn_type_param ::= [ IDENT ':' ] type

named_type    ::= IDENT { '.' IDENT }

builtin_type  ::= 'u8' | 'u16' | 'u32' | 'u64'
               | 'i8' | 'i16' | 'i32' | 'i64'
               | 'f32' | 'f64'
               | 'usize' | 'bool' | 'byte' | 'anyptr'

Statements

stmt          ::= block_stmt
               | if_stmt
               | while_stmt
               | for_stmt
               | switch_stmt
               | var_decl_stmt
               | continue_stmt
               | break_stmt
               | return_stmt
               | return_err_stmt
               | return_ok_stmt
               | defer_stmt
               | when_stmt
               | link_decl           -- legal anywhere a stmt is, but always a sema
                                         error here — parses so the diagnostic can name it precisely
               | diagnostic_decl     -- same as link_decl above — always a sema error as a stmt
               | expr_stmt

block_stmt    ::= '{' { stmt } '}'

if_stmt       ::= 'if' expr stmt [ 'else' stmt ]

while_stmt    ::= 'while' expr block_stmt

when_stmt     ::= 'when' expr block_stmt [ 'else' ( when_stmt | block_stmt ) ]

-- 'expr' must be a compile-time constant expression (a sema error otherwise).
-- Both branches are always type-checked; only the selected branch's statements
-- are emitted by codegen. The 'then' branch (and each block in an 'else'/
-- 'else when' chain) must be a literal block_stmt, unlike if_stmt's 'stmt'
-- which accepts any statement.

for_stmt      ::= 'for' for_binding 'in' for_iterable block_stmt

for_binding   ::= '&' IDENT                    -- for &val in ...: element bound by reference
               | IDENT [ ',' [ '&' ] IDENT ]   -- for val in ...  OR  for idx, [&]val in ...

for_iterable  ::= '..' expr             -- upper-bound-only range; lower bound defaults to 0
               | expr [ '..' expr ]     -- a slice/array, or a lower..upper range

switch_stmt   ::= 'switch' expr '{' [ switch_arm { ',' switch_arm } [ ',' ] ] '}'

switch_arm    ::= arm_pattern ':' stmt

continue_stmt ::= 'continue'
break_stmt    ::= 'break'
return_stmt   ::= 'return' [ expr { ',' expr } ]
return_err_stmt ::= 'return_err' expr
return_ok_stmt  ::= 'return_ok' [ expr { ',' expr } ]
defer_stmt    ::= 'defer' stmt
expr_stmt     ::= expr

var_decl_stmt ::= ( 'mut' | 'const' ) IDENT
                  ( ':' type [ '=' expr ]
                  | ',' IDENT { ',' IDENT } ':=' expr   -- group decl
                  | ':=' expr )

-- In a group decl, any name position may be '_' (an ordinary identifier) to discard that slot

Expressions — Precedence (low → high)

expr          ::= assign_expr | import_expr

import_expr   ::= 'import' '(' STRING ')' { '.' IDENT }
                  -- only valid as the initializer of 'const :=' with no type annotation;
                  -- the optional trailing '.' IDENT chain is a shortcut for pulling one
                  -- value out of the module without binding it to its own name first —
                  -- see the Compile-Time Configuration page

assign_expr   ::= when_expr [ assign_op assign_expr ]   -- right-associative

assign_op     ::= '=' | '+=' | '-=' | '*=' | '/='
               | '&=' | '|=' | '^=' | '<<=' | '>>=' | '~='
                  -- '~=' (toggle-assign) is legal only when the target is a bitset type

when_expr     ::= ternary_expr [ 'when' ternary_expr 'else' expr ]

-- 'then_val when cond else else_val' binds looser than every binary operator
-- (including ternary '?:') but tighter than assignment. Both branches must
-- have the same type. When 'cond' is a compile-time constant, only the
-- selected branch is emitted by codegen (both are still type-checked); when
-- 'cond' is a runtime value, this behaves exactly like ternary '?:'. A bare
-- unparenthesized nested 'when...else' in 'cond' position does not parse —
-- see the Compile-Time Configuration page.

ternary_expr  ::= logical_or_expr [ '?' expr ':' expr ]   -- right-assoc

logical_or_expr  ::= logical_and_expr { '||' logical_and_expr }

logical_and_expr ::= in_expr          { '&&' in_expr }

in_expr          ::= bitwise_or_expr  [ 'in' bitwise_or_expr ]
                  -- bitset membership testing; non-chaining ('in's result is bool, not a
                  -- bitset). Unrelated to 'for'-loop's 'in' — that one is consumed directly
                  -- by the 'for' statement's own grammar and never reaches this production.
                  -- See the Structs & Types page's "Bitsets" section.

bitwise_or_expr  ::= bitwise_xor_expr { '|'  bitwise_xor_expr }

bitwise_xor_expr ::= bitwise_and_expr { ( '^' | '~' ) bitwise_and_expr }
                  -- infix '~' is accepted at the same precedence as '^' — same lowering
                  -- (bitwise XOR for integers, symmetric difference for two bitsets). No
                  -- ambiguity with prefix '~' (unary complement): precedence-climbing only
                  -- reads '~' as prefix at the START of an operand, never here.

bitwise_and_expr ::= equality_expr    { '&'  equality_expr }

equality_expr    ::= comparison_expr  { ( '==' | '!=' ) comparison_expr }

comparison_expr  ::= shift_expr  { ( '<' | '>' | '<=' | '>=' ) shift_expr }

shift_expr    ::= additive_expr { ( '<<' | '>>' ) additive_expr }

additive_expr ::= mult_expr     { ( '+' | '-' ) mult_expr }

mult_expr     ::= unary_expr    { ( '*' | '/' | '%' ) unary_expr }

unary_expr    ::= try_expr
               | ( '-' | '!' | '~' | '&' | '++' | '--' ) unary_expr
               | postfix_expr

-- dereference is NOT a prefix operator here — there is no C-style '*p' in Mirage.
-- it's the postfix_op '.' '*' below: 'p.*'

try_expr      ::= 'try' postfix_expr

-- 'try' has tighter binding than binary operators

postfix_expr  ::= primary_expr { postfix_op }

postfix_op    ::= '(' [ arg { ',' arg } ] ')'                       -- call
               | '.' IDENT                                          -- member (auto-derefs through a pointer)
               | '.' IDENT '{.' field_init { ',' field_init } '}'  -- qualified tagged variant
               | '.' '*'                                            -- dereference: 'p.*' reads/writes the pointee
               | '[' expr ']'                                       -- index
               | '[' [ expr ] '..' [ expr ] ']'                     -- slice range; both bounds optional
                                                                          (absent lower = 0, absent upper = length)
               | '++'                                               -- post-increment
               | '--'                                               -- post-decrement

arg           ::= expr '...'    -- spread; only legal as the sole, final argument
                                    of a call whose callee has a native '...T' parameter
               | expr

Primary Expressions

primary_expr  ::= INT_LITERAL
               | FLOAT_LITERAL
               | STRING_LITERAL
               | CHAR_LITERAL
               | 'true'
               | 'false'
               | 'nil'
               | 'iota'
               | 'default'
               | 'undefined'
               | IDENT
               | '(' expr ')'
               | sizeof_expr
               | len_expr
               | cast_expr
               | stackalloc_expr
               | import_bin_expr
               | match_expr
               | braced_initializer
               | dot_ident_expr
               | contextual_tagged_variant
               | option_expr
               | env_expr

option_expr   ::= '#option' '(' STRING [ ',' expr ] ')'

env_expr      ::= '#env' '(' STRING [ ',' expr ] ')'

-- '#' is a sigil, not part of an identifier; 'option'/'env' (like 'link' above) are
-- parsed as plain identifiers immediately following it, not reserved
-- keywords. Legal anywhere primary_expr is legal — nested inside arithmetic,
-- as a call argument (including '#link's data), as a 'mut' initializer, etc.
-- Each value is resolved once — from '--opt'/the default for option_expr, from
-- the named environment variable/the default for env_expr — and cached, so it
-- composes as an ordinary compile-time-constant expression wherever it's
-- written. See the Compile-Time Configuration page for the target-type
-- resolution priority and value-coercion rules (identical for both).

sizeof_expr   ::= 'sizeof' '(' sizeof_operand ')'

sizeof_operand ::= type   -- whenever the next token(s) can only start a type
                              (builtin keyword, '*', '[', 'struct', 'enum', 'union', 'bitset', 'fn', 'trait')
               | expr     -- otherwise (may still simply name a type, e.g. module.TypeName)

len_expr      ::= 'len' '(' expr ')'

cast_expr     ::= 'cast' '(' expr ',' type [ ',' expr ] ')'

stackalloc_expr ::= 'stackalloc' '(' expr ')'
                  -- runtime-sized stack allocation, evaluates to anyptr

import_bin_expr ::= 'import_bin' '(' STRING ')'
                  -- embeds a file's bytes at compile time as a [N]u8 constant

match_expr    ::= 'match' expr '{' [ match_arm { ',' match_arm } [ ',' ] ] '}'

match_arm     ::= arm_pattern ':' expr

arm_pattern   ::= '.' IDENT [ '(' [ '&' ] IDENT ')' ]   -- variant (enum/tagged-union)
               | '_'                                       -- default / wildcard (must be last)
               | expr                                      -- literal constant

dot_ident_expr ::= '.' IDENT              -- enum literal; requires expected-type context
               | '.' IDENT '(' expr ')'   -- sugar for '.' IDENT '{.v = expr}' (single
                                             non-struct payload only)

contextual_tagged_variant   ::= '.' IDENT '{.' field_init { ',' field_init } '}'
                                -- '{.' disambiguates from block statements

field_init    ::= '.' IDENT '=' expr

bitset_literal ::= '{' '.' IDENT { ',' '.' IDENT } '}'
                  -- a bitset member set; only legal where a bitset type is expected —
                  -- see the Structs & Types page's "Bitsets" section

braced_initializer ::= '{' '}'                                        -- empty (full default)
               | '{' field_init { ',' field_init } '}'             -- struct fields
               | bitset_literal
               | '{' expr { ',' expr } [ '...' ] '}'                  -- array values, optional trailing fill
               -- Disambiguation: '.' IDENT '=' is struct form; '.' IDENT with no '='
               -- (comma or '}' follows instead) is the bitset form; otherwise array form.
               -- Mixing the two '.' IDENT forms in one initializer is a parse error.

Literals

INT_LITERAL   ::= decimal_int | hex_int | bin_int

decimal_int   ::= DIGIT { DIGIT | '_' }
hex_int       ::= ( '0x' | '0X' ) HEX_DIGIT { HEX_DIGIT | '_' }
bin_int       ::= ( '0b' | '0B' ) BIN_DIGIT { BIN_DIGIT | '_' }

FLOAT_LITERAL ::= DIGIT { DIGIT } '.' DIGIT { DIGIT }

STRING_LITERAL ::= '"' { char | escape_seq } '"'

CHAR_LITERAL  ::= "'" ( char | escape_seq ) "'"
               -- always type u8; there is no distinct character type

escape_seq    ::= '\\' | '\"' | "\'" | '\n' | '\t' | '\r'
               | '\x' HEX_DIGIT HEX_DIGIT                        -- exactly two hex digits
               | '\' OCTAL_DIGIT [ OCTAL_DIGIT [ OCTAL_DIGIT ] ]  -- 1-3 octal digits, max 0xFF

IDENT         ::= LETTER { LETTER | DIGIT | '_' }

DIGIT         ::= '0' .. '9'
HEX_DIGIT     ::= '0' .. '9' | 'a' .. 'f' | 'A' .. 'F'
OCTAL_DIGIT   ::= '0' .. '7'
BIN_DIGIT     ::= '0' | '1'
LETTER        ::= 'a' .. 'z' | 'A' .. 'Z' | '_'

Syntax Notes

Field Separators

ContextSeparator
Struct fields in type definitionNone required; optional ; tolerated
Enum variants in type definitionNone required; optional ; tolerated
Tagged/untagged union members in type definitionNone required; optional ; tolerated
Struct braced initializer {.x = 1, .y = 2}Comma
Array braced initializer {1, 2, 3}Comma
Match / switch armsComma (trailing comma optional)
Function parametersComma
Multiple return values in return / return_okComma

The ; token is not really a "separator" in the usual sense — the parser simply skips any number of stray semicolons wherever it looks for one. This is what makes a one-line form like struct { w: f64; h: f64 } valid; commas are never accepted in these positions.

Braced Initializer Disambiguation

The sequence {. (left-brace immediately followed by dot) signals a struct or tagged union field initializer: {.field = val}. Any other content after { is an array initializer, empty initializer {}, or a block statement. This disambiguation applies to struct inits, tagged union payload constructors (postfix Type.variant{. and primary .variant{.), and inline struct returns.

Multi-Return Syntax

Multi-return type annotations require parentheses: -> (T1, T2). Multi-return return/return_ok statements use commas: return a, b. Multi-return calls use group declarations: mut a, b := call().

try Precedence

try is parsed at the unary level, tighter than binary operators. try f(x) + g() parses as (try f(x)) + g(). Use parentheses to chain member access: (try f(x)).field.

Reserved Keywords

bitset break byte cast const continue default defer else enum error ext false fn for if impl import import_bin in iota len macro match mut nil pub return return_err return_ok sizeof stackalloc struct switch trait true try type undefined union while

ext is scanned as a plain identifier, not a keyword token — it's only special at the very start of a declaration in ext fn name(...) form.

Reserved for future use
namespace, asm, when, and offsetof are also reserved lexer keywords, but nothing in the language currently consumes them — using any of these identifiers today is a parse error, even though no feature is implemented for them yet.
