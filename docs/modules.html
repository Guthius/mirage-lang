Modules

Splitting code across directories with import and pub.

Importing a Module

A module is a directory containing one or more .mir files (all merged together as one module — see Getting Started). You import one using the import expression, which must appear as the initializer of a const declaration with no explicit type: 

const mem := import("mem")
const vec := import("vector")

The import result is a namespace binding — it is not a value and cannot be assigned, passed as an argument, or stored.

How the Path Is Resolved

The string is resolved in two steps:

  1. First, relative to the importing module's own directory: <importing-module-dir>/<path>. If that's a directory, it's used.
  2. Otherwise, relative to the directory named by the MIRAGE_PATH environment variable, if set — and the result must stay inside MIRAGE_PATH (no escaping it with ../).

In practice: keep modules that are specific to one project as subdirectories next to the code that imports them, and put anything meant to be shared across unrelated projects under the directory pointed to by MIRAGE_PATH. 

# project/
#   main/
#     main.mir        -- import("../lib/vector") reaches project/lib/vector
#   lib/
#     vector/
#       main.mir

Accessing Module Symbols

After importing, you access the module's public symbols through the namespace name using dot notation: 

const mem := import("mem")

fn example() {
    mut ptr: anyptr = mem.malloc(64)     # call a function
    mem.free(ptr)
    mut v: mem.SomeType                    # use a type
}

Visibility with pub

Declarations in a module are private by default. To make them accessible from other modules, add pub: 

# vector/main.mir

const mem := import("mem")

# Public — visible outside this module
pub type vector = struct {
    data:         anyptr
    length:       usize
    capacity:     usize
    element_size: usize
}

pub fn create(v: *vector, element_size: usize) -> bool {
    v.data         = nil
    v.length       = 0
    v.capacity     = 0
    v.element_size = element_size
    return true
}

# Private — not accessible from importing modules
fn reserve(v: *vector, cap: usize) -> bool {
    # ...
    return true
}

Methods and Modules

Methods on a type are visible cross-module only if they are individually marked pub. The impl block itself cannot be pub. 

# vector/main.mir
impl vector {
    pub fn push(self, element: anyptr) -> bool {
        # ...
    }

    pub fn at(self, idx: usize) -> anyptr {
        # ...
    }
}

# main/main.mir
const vec := import("vector")

pub fn main() -> i32 {
    mut v: vec.vector
    vec.create(&v, sizeof(v))

    const x: i32 = 42
    v.push(&x)   # method call on cross-module type

    const result := *cast(v.at(0), *i32)
    return result
}

Chained Module Access

If a module re-exports another module via pub const, you can chain access:

# lib/main.mir
pub const utils := import("utils")

# main/main.mir
const lib := import("lib")

pub fn main() {
    lib.utils.do_something()
}

Global Variables

Top-level mut and const declarations are module-level globals. They live for the lifetime of the program and are accessible from anywhere in the same module (or cross-module if pub). 

# mem/main.mir
mut heap_head: *block_header = nil
mut heap_tail: *block_header = nil

pub mut allocation_count: u64 = 0

pub const alignment: usize = 16

Embedding Files: import_bin

import_bin("path") embeds a file's raw bytes into the compiled binary at compile time, as a fixed-size array constant of type [N]u8 where N is the file's size in bytes. It's useful for baking small assets — shaders, icons, default config files — directly into the executable so there's nothing extra to ship at runtime. 

const banner := import_bin("assets/banner.txt")   # banner: [N]u8

printf("%.*s\n", cast(len(banner), i32), &banner[0])

Unlike import, the path is resolved relative to the importing module's own directory only, and it must not escape that directory (no ../ traversal out of the module). A missing or unreadable file is a compile error; a file larger than 1 MiB still compiles, but emits a warning, since embedding very large files bloats the executable.

Complete Module Example

Here is a minimal two-module example. math/main.mir provides arithmetic utilities; app/main.mir imports and uses them.

# math/main.mir

pub fn abs(x: i32) -> i32 {
    return x < 0 ? 0 - x : x
}

pub fn clamp(x: i32, lo: i32, hi: i32) -> i32 {
    if x < lo { return lo }
    if x > hi { return hi }
    return x
}
# app/main.mir

ext fn printf(fmt: *u8, ...) -> i32
const math := import("../math")

pub fn main() {
    printf("%d\n", math.abs(-5))           # 5
    printf("%d\n", math.clamp(15, 0, 10))  # 10
}
