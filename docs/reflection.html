Reflection

type_of, type_info_of, and the any fat-pointer type — compile-time-unique type identity, type-erased values, and runtime type descriptions.

Mirage's reflection system has three parts that build on each other: type_of gives every type in a program a stable, comparable identity; any is a type-erased container that carries that identity alongside a data pointer, so a value's type can travel with it at runtime; and type_info_of turns that identity into a structured, inspectable description — field names, offsets, sizes — for the types that actually need one.

None of this requires generics or a garbage collector. There is no hidden per-object metadata: a plain struct is still just its bytes, and only the values you explicitly wrap in any or ask type_of about ever touch the reflection system at all.

The type Type

type is a builtin type: a compile-time-unique identifier for a type, backed by a u64. It supports only == and != — no arithmetic, no ordering, and no literal syntax of its own. The only way to produce a type value is type_of. 

if size_of(type) != 8 { // always false — type is 8 bytes
    return 1
}

type_of

const t1 := type_of(i32)           // compile-time constant
const t2 := type_of(my_i32_var)    // compile-time constant — uses the variable's static type
const t3 := type_of(my_any_var)    // RUNTIME — reads my_any_var's type id

type_of(expr_or_type) returns its operand's type identity. The operand may be a type written directly (type_of(u64), type_of(*u8), type_of(SomeStruct)) or an arbitrary expression, whose static type is used — the parser disambiguates the two exactly like size_of/align_of do: a token that can only begin a type is parsed as a type, anything else as an ordinary expression.

Two type_of calls on the same type always compare equal, regardless of how many times or where in the program they're written: 

type Point = struct { x: i32; y: i32 }

if type_of(i32) != type_of(i32) { return 1 }   // never true
if type_of(i32) == type_of(u32) { return 1 }   // never true — different types

const p: Point = {.x = 1, .y = 2}
if type_of(p) != type_of(Point) { return 1 }  // never true — a value and its named type match
Compile-time, except for any
type_of is a compile-time constant for every operand — usable anywhere a constant is required, including a global initializer — except when the operand's resolved type is any. In that one case it lowers to a runtime read of the value's type id, since an any's underlying type isn't known until runtime.

The any Type

any is a fat pointer that erases a value's type: { id: type, data: anyptr }, 16 bytes, 8-byte aligned. Any value is implicitly coerced to any wherever any is the expected type — call arguments, return statements, variable initializers — the same expected-type mechanism used by tagged-union and trait-handle coercion: 

const x: i32 = 42
const a: any = x           // OK — x is addressable
const b: any = 42          // ERROR — 42 is not addressable

mut tmp: i32 = 42
const c: any = tmp         // OK
The source must be addressable
Coercing a non-addressable value — a bare literal, an arithmetic result, a function call's return value — to any is a sema error, because the coercion needs to take the value's address: 
error: cannot coerce non-addressable value to 'any'; bind it to a variable first.
Bind the value to a const or mut first, as with c above, and the coercion works.

The coercion produces { id: type_of(T), data: &value }, where T is the source's own type. If the source is already anyptr, data is that pointer directly, rather than taking its address again.

any has no fields
It's a fat pointer, not a struct — a.id and a.data are both a sema error: 
error: 'any' has no field 'id'
Its two words are reached through dedicated operations instead, described below.

The type identity is type_of(a) — the same function used everywhere else in the reflection system, just evaluated at runtime for an any operand instead of resolved at compile time: 

const a: any = my_i32
if type_of(a) == type_of(i32) { // ... }

The data pointer comes from cast: any is a legal cast source, but only to a pointer type or anyptr — casting to anything else is a sema error: 

error: 'any' may only be cast to a pointer type or 'anyptr'.
const test_var: any = my_i32
const val: i32 = cast(test_var, *i32).*
const p: anyptr = cast(test_var, anyptr)

The cast performs no type-id check — the programmer is responsible for the target type matching type_of(test_var), same posture as every other anyptr cast.

The runtime/type_info Module

type_info_of (below) returns a raw anyptr — to actually read it, cast it to *Type_Info, a type defined not by the compiler but by a small stdlib module you import explicitly: 

const rt := import("runtime/type_info")

Type_Info is a tagged union with one variant per kind of type it can describe — Struct, Enum, Union, Tagged_Union, Bitset, Pointer, Slice, Array, Function, Trait, and Error_Type. Each variant carries exactly the fields you'd expect — a struct's field names and byte offsets, an enum's variant names and values, and so on. Type_Kind is a parallel enum used for a couple of "what scalar backs this" fields (an enum or bitset's storage type). Being ordinary Mirage source, you can read its full field list directly: it's just a union(enum) and a handful of small structs, no compiler magic.

Error_Type carries its member types plus an is_optional: bool recording whether the type was spelled ?error(...) — an error a caller may leave unhandled (see Ignorable Errors). The marking is visible here because it is part of the type's identity: error(E) and ?error(E) are two distinct types with two distinct Type_Info records.

Not auto-imported
Unlike builtin types, runtime/type_info is a regular stdlib module. Nothing in the compiler auto-imports it — a program that never calls type_info_of pays nothing for it, not even a symbol in the binary.

type_info_of

const info: *rt.Type_Info = cast(type_info_of(type_of(my_var)), *rt.Type_Info)

type_info_of(expr) takes an operand of type type or any — anything else is a sema error naming the fix: 

error: type_info_of() requires an argument of type 'type' or 'any'; got 'i32'.
       Use 'type_of(expr)' to get the type ID first.

It always returns anyptr, and is nil for every builtin scalar type (u8..f64, usize, bool, byte, anyptr, error) — only compound and user-defined types get a real Type_Info. Check for nil before casting: 

if type_info_of(type_of(i32)) != nil { return 1 }  // never true — i32 is a builtin scalar

Example: Introspecting a Struct

Casting the result and switching on the tagged union gives structured access to a type's shape. Field names come back as []u8, so comparing them needs an ordinary byte comparison — there's no built-in string equality operator: 

const rt := import("runtime/type_info")

type Point = struct {
    x: i32
    y: i32
}

fn str_eq(a: []u8, b: []u8) -> bool {
    if len(a) != len(b) { return false }
    mut i: usize = 0
    while i < len(a) {
        if a[i] != b[i] { return false }
        i += 1
    }
    return true
}

pub fn main() -> i32 {
    const info_ptr := type_info_of(type_of(Point))
    if info_ptr == nil { return 1 }

    const info: *rt.Type_Info = cast(info_ptr, *rt.Type_Info)
    switch info.* {
        .Struct(s): {
            if !str_eq(s.name, "Point") { return 1 }
            if s.size != 8 { return 1 }
            if len(s.fields) != 2 { return 1 }
            if !str_eq(s.fields[0].name, "x") { return 1 }
            if s.fields[0].offset != 0 { return 1 }
            if !str_eq(s.fields[1].name, "y") { return 1 }
            if s.fields[1].offset != 4 { return 1 }
        },
        _: { return 1 },
    }
    return 0
}

Example: A Generic print_any

The combination that makes reflection useful day to day: a ...any variadic parameter (any value implicitly coerces to any, including at a variadic call site) plus type_of comparisons to dispatch on the value's real type at runtime: 

fn print_any(b: *builder.StringBuilder, a: any) -> bool {
    const t := type_of(a)

    if t == type_of(i32) {
        const val: i32 = cast(a, *i32).*
        mut buf: [11]u8 = undefined
        return builder.put_str(b, string.from_i32(buf, val))
    }
    if t == type_of(bool) {
        const val: bool = cast(a, *bool).*
        return builder.put_str(b, val ? "true" : "false")
    }
    if t == type_of([]u8) {
        const val: []u8 = cast(a, *[]u8).*
        return builder.put_str(b, val)
    }

    // Unknown type — fall back to a generic "<type>" if a Type_Info exists at all.
    return type_info_of(a) != nil ? builder.put_str(b, "<type>") : builder.put_str(b, "<unknown>")
}

Called as print_any(&b, name), print_any(&b, x), print_any(&b, flag) — each argument is coerced to any at the call site, and print_any figures out what it actually got. This is exactly the shape a println(format, args: ...any)-style formatter uses to accept arbitrary argument types without generics.

Indirect type_info_of works too
Storing a type_of result and passing it to type_info_of later — rather than writing type_info_of(type_of(T)) directly — works exactly the same way: 
const t := type_of(Point)
// ... t travels through other code, gets stored, passed around ...
const info := type_info_of(t)   // still finds Point's Type_Info
The direct type_info_of(type_of(T)) spelling resolves to a specific compile-time global; every other case — a stored type value, or an any — resolves through a sorted lookup table with an inline binary search at runtime. Either way, every type ever passed to type_of anywhere in the program gets an entry, so which spelling you use only affects how the lookup is compiled, never whether it succeeds.

Summary

FeaturePurpose
typeA compile-time-unique, comparable identity for a type. 8 bytes, ==/!= only.
type_of(expr_or_type)Produces a type value. Compile-time constant, except for an any operand.
anyA type-erased fat pointer: { id: type, data: anyptr }. Implicit coercion from any addressable value.
