Compile-Time Configuration

Reading build-time flags and environment variables, and conditionally compiling declarations, statements, and linker inputs with #option, #env, #link, #error/#warn, and when.

Seven coupled features let a module read configuration supplied by the compiler driver or the host environment, act on it entirely at compile time — no runtime branching, no dead code left in the binary — and surface configuration problems as compiler diagnostics:

  • #option — reads a value passed with --opt key=value.
  • #env — reads a value from an environment variable, otherwise identical to #option.
  • the when statement — compiles only the selected branch's declarations or statements.
  • the when expression — folds to one branch's value at compile time (or behaves like a runtime ternary otherwise).
  • #link — declares a linker input (library, system library, or raw flag) conditionally.
  • #error/#warn — emits a compile-time error/warning with a custom message, typically guarded by when.

Together they replace what other languages solve with build scripts, #ifdef, or separate per-platform source trees: the same .mir files handle every target, and the compiler driver picks the target via --opt.

#option

#option(key)
#option(key, default)

A compile-time expression that reads a value supplied via --opt key=value on the command line (repeatable, one per flag). key is a string literal — by convention a /-separated path such as "build/target_os". If a default is given, it's used whenever the matching --opt wasn't passed; without a default, a missing --opt is a compile error: 

error: required option 'build/target_os' was not provided.
       Pass it with: --opt build/target_os=<value>

Where It Can Appear

#option is a normal expression — legal anywhere an expression is legal, including nested inside arithmetic, passed straight as a function argument (#link's data argument included), or as a mut variable's initializer. Its value is resolved once from --opt/the default and cached, so it behaves as an ordinary compile-time-constant wherever it's written: 

// no need to bind it to a const first
#link(lib, #option("wasm_lib", "libraylib.web.a"))

mut retries := #option("max_retries", 3) + 1   // retries is mut afterward

Target Type

The type #option coerces the raw --opt string into is chosen in this order:

  1. The expected type from context — e.g. a const's declared type.
  2. If no expected type is known but a default is given, the default value's own type.
  3. Otherwise, []u8 — the raw string, unconverted.
Target type--opt value
bool"true"/"1" → true, "false"/"0" → false (case-insensitive)
Integer typesparsed as a decimal integer; out-of-range or non-numeric is an error
[]u8the raw string, unconverted
Enum typesmatched by variant name first (Windows), then by integer value (1)
Anything elsea compile error — unsupported
pub type OperatingSystem = enum {
    Linux
    Windows
    Other
}

pub type Architecture = enum {
    X86
    X86_64
    Arm64
    Wasm32
    Wasm64p32
    Other
}

pub const target_os:   OperatingSystem = #option("build/target_os",   .Linux)
pub const target_arch: Architecture    = #option("build/target_arch", .X86_64)

Both consts default to Linux/X86_64, but building with --opt build/target_os=Windows (or --opt build/target_os=1, the enum's integer value) selects .Windows instead. A module like this is typically shared and imported wherever target-specific decisions are made — see the full example below.

#env

#env(key)
#env(key, default)

Identical to #option in every respect — legality, target-type resolution, value coercion, and the required-value error shape — except key names an environment variable instead of a --opt key, and the value is read once at compile time (on the machine running the compiler) instead of coming from the command line: 

error: required environment variable 'MIRAGE_TARGET_ARCH' was not set.
       Set it with: MIRAGE_TARGET_ARCH=<value>
pub const target_os:   OperatingSystem = #env("MIRAGE_TARGET_OS",   .Linux)
pub const target_arch: Architecture    = #env("MIRAGE_TARGET_ARCH", .X86_64)

#option and #env can be mixed freely — including reading the same key from both, e.g. an #option whose own default is an #env lookup, so a --opt flag overrides an environment variable which in turn overrides a hardcoded default: 

const retries := #option("max_retries", #env("MIRAGE_MAX_RETRIES", 3))

The when Statement

when condition {
    ...
} else when other_condition {
    ...
} else {
    ...
}

A compile-time conditional statement, legal anywhere an ordinary statement is legal — function bodies, module scope, or nested inside other when/if/while blocks. condition must be a compile-time constant expression; a runtime value is a compile error pointing you at if instead.

Both branches are always type-checked
This is deliberate and has no opt-out: it stops platform-specific code from silently rotting when you're developing on a different target than a given branch is for. Only the selected branch is ever emitted — the other branch's code is never executed and never even reaches codegen (an ext fn declared only in an unselected branch never gets an LLVM declaration synthesized for it).

At Module Scope

A module-scope when block may only contain #link, #error, and #warn declarations, const declarations initialized directly with #option/#env, type declarations, and ext fn declarations. Anything else is a compile error. This restricted set is exactly what's needed for platform-specific externs, type aliases, and configuration validation: 

when target_os == .Windows {
    ext fn GetLastError() -> u32
    pub type long = i32   // Windows' 'long' stays 32-bit even on x64
} else {
    pub type long = i64
}

A name declared only inside a module-scope when's selected branch is an ordinary symbol wherever it's visible. A name declared only in the unselected branch simply doesn't exist — referencing it, even from the other branch of the same when, is a plain "unknown identifier" error.

The when Expression

then_val when condition else else_val

Binds looser than every binary operator (including the ternary ?:) but tighter than assignment. Both branches must have the same type, same as ternary — see Control Flow. What sets it apart is that its behavior depends on whether condition is a compile-time constant:

  • Compile-time constant — both branches are still type-checked, but only the selected branch's value is ever computed; the other side is never emitted, so it can safely reference platform-specific data that wouldn't exist on the current target.
  • Runtime value — behaves exactly like the ternary ?:: both branches are emitted and the result is chosen at runtime.

The ordinary ternary ?: also folds to a compile-time constant when its condition and both branches are themselves constants, so it works fine anywhere a constant is required — like #link's data argument: 

#link(lib, raylib_shared ? "raylibdll.lib" : "raylib.lib")   // folds fine
Prefer when/else for platform-specific branches
The difference that survives is where the unselected branch's code gets skipped. when/else skips it everywhere, including plain runtime-looking expressions — so it's still the right choice when a branch references something that only makes sense on one target (an ext fn only declared for that platform, say). Plain ?: only skips emitting the unselected side when the whole expression sits somewhere a constant is required in the first place; used as an ordinary value it always builds a runtime branch, even with two literal operands. 
// right for a value that only needs to be constant-foldable
#link(lib, "raylibdll.lib" when raylib_shared else "raylib.lib")

// right when a branch wouldn't even compile on the other target
const err_code := GetLastError() when target_os == .Windows else 0   // GetLastError only exists on Windows

#link

#link(category, data)
CategoryMeaning
libdata is a library file path, relative to the current module file's directory
systemdata is a system library name, searched in the linker's default paths
flagdata is passed to the linker verbatim, as a raw flag

category is a bare identifier (lib, system, or flag), not a string. data must be a compile-time constant []u8 expression — a when expression is legal here, which is how shared-vs-static or per-platform library names are usually selected: 

#link(lib, "raylibdll.lib" when raylib_shared else "raylib.lib")

#link is legal only at module scope, or inside a module-scope when block — anywhere else (a function body, an if, etc.) it's a compile error. The compiler collects every #link reachable from a live when branch, across every compiled module, into one list for the driver to act on; directives in an unselected branch are type-checked but never collected.

#error / #warn

#error(message)
#warn(message)

Compile-time diagnostic directives: #error emits a compiler error at the directive's location, #warn a warning. message must be a compile-time constant []u8 expression, exactly like #link's data argument. Used on their own they're unconditional — #error(...) reached anywhere in a live position always fails the build. Their real job is inside a when block, rejecting or flagging a bad configuration right where it's selected instead of failing later with a more confusing, indirect error: 

when target_os == .Windows {
    #error("Windows is not supported")
} else when target_arch == .Wasm32 {
    #warn("Wasm32 support is experimental")
}

Like #link, #error/#warn are legal only at module scope, or inside a module-scope when block — anywhere else it's a compile error. And like every other module-scope when directive, the unselected branch's message argument is still fully type-checked, it just never actually emits the diagnostic.

Combining With Modules

Configuration is usually centralized in one shared module (an Options module, say) and imported wherever a target-specific decision needs to be made. When you only need a single value from it, you can chain a .field access straight onto import(...) instead of binding the whole module to its own name first: 

const target_os := import("../../Core/Build/Options").target_os
const target_arch := import("../../Core/Build/Options").target_arch

This is exactly equivalent to the two-step form (const opts := import(...), then opts.target_os elsewhere) — it's only a shortcut for the common case of pulling out one value. import(...) is still not a value in any other sense: the result of the call itself can't be assigned, passed as an argument, or stored, and only a plain .field chain (optionally several deep, e.g. import("m").a.b when a re-exports another module) is accepted directly after it — never a call or index. See Modules for the general import syntax.

Complete Example

A shared options module, imported and used to drive platform-specific linking for a raylib binding:

// Core/Build/Options/main.mir

pub type OperatingSystem = enum {
    Linux
    Windows
    Other
}

pub type Architecture = enum {
    X86
    X86_64
    Arm64
    Wasm32
    Wasm64p32
    Other
}

pub const target_os:   OperatingSystem = #option("build/target_os",   .Linux)
pub const target_arch: Architecture    = #option("build/target_arch", .X86_64)
// raylib_binding/main.mir

const target_os     := import("../../Core/Build/Options").target_os
const target_arch   := import("../../Core/Build/Options").target_arch
const raylib_shared := #option("raylib/shared", false)

// Windows
when target_os == .Windows {
    #link(flag, "/NODEFAULTLIB:msvcrt" when raylib_shared else "/NODEFAULTLIB:libcmt")
    #link(lib, "windows/raylibdll.lib" when raylib_shared else "windows/raylib.lib")

    #link(system, "Winmm")
    #link(system, "Gdi32")
    #link(system, "User32")
    #link(system, "Shell32")
}

// Linux
when target_os == .Linux {
    when target_arch == .X86_64 {
        #link(lib, "linux_x86_64/libraylib.so.600" when raylib_shared else "linux_x86_64/libraylib.a")
    } else {
        #link(system, "raylib")
    }
}

// WebAssembly
when target_arch == .Wasm32 || target_arch == .Wasm64p32 {
    #link(lib, #option("raylib/wasm_lib", "wasm/libraylib.web.a"))
}

// Windows has 32-bit 'long' even on x64...
when target_os == .Windows {
    pub type long = i32
} else {
    pub type long = i64
}

Building this with ./build/mirage build raylib_binding --print-link-directives emits lib linux_x86_64/libraylib.a by default; add --opt build/target_os=Windows --opt raylib/shared=true and it emits the Windows shared-library set instead — with no runtime branch anywhere in the compiled output.
