Control Flow

Conditionals, loops, and pattern matching.

If / Else

The if statement evaluates a bool condition and executes the then branch if true.

if x > 0 {
    printf("positive\n")
} else if x < 0 {
    printf("negative\n")
} else {
    printf("zero\n")
}
  • The condition must be exactly bool — no implicit integer-to-bool coercion.
  • The else branch is optional.
  • The body can be any statement, including a non-block single statement.

Ternary Expression

For simple conditional values, use the ternary operator:

const abs: i32 = x < 0 ? 0 - x : x

While Loop

while repeatedly executes the body block as long as the condition is true. The body must be a block statement. 

mut i: i32 = 0
while i < 10 {
    printf("%d\n", i)
    i++
}

Infinite Loop

while true {
    # runs forever until break
    if done { break }
}

Loop with Decrement Condition

Since -- is a post-decrement expression, it can be used directly as the while condition:

mut n: usize = 5
while n-- {
    # runs 5 times: n is tested before decrement
}

For Loop

for iterates a range, or the elements of a slice or fixed-size array. It always binds one or two names between for and in. 

for x in 0..10 {
    printf("%d\n", x)     # 0, 1, 2, ..., 9 (upper bound is exclusive)
}

for x in ..10 {
    # same as 0..10 — lower bound defaults to 0
}

Iterating a slice or array binds the element by value, or by index and value:

const names: [3]*u8 = {"alice", "bob", "carol"}

for name in names {
    printf("%s\n", name)
}

for i, name in names {
    printf("%zu: %s\n", i, name)
}

Prefix the element binding with & to bind a pointer to the element in place — mutating through it mutates the underlying slice or array, instead of working on a copy: 

mut scores: [3]i32 = {1, 2, 3}

for &s in scores {
    s.* *= 10   # scores becomes {10, 20, 30}
}

for i, &s in scores {
    s.* += cast(i, i32)
}
Dereferencing is postfix: s.*, not *s
Mirage has no C-style prefix dereference. To read or write the whole value a pointer points to, use the postfix .* operator. See Types for details — this only matters for the whole pointee; ptr.field already auto-derefs.
Discarding a binding
Any binding name may be _ to discard it, e.g. for _, name in names when only the value is needed but the two-binding form reads better at a call site.

Break and Continue

mut i: i32 = 0
while i < 10 {
    i++
    if i == 3 { continue }  # skip 3
    if i == 7 { break }     # stop at 7
    printf("%d\n", i)
}
Defer in Loops
A defer inside a loop body fires on every iteration (including on break and continue). See Error Handling.

Match Expression

match is an expression — it has a result value. All arms must produce the same type. Match is exhaustive: the compiler checks that all possible values are covered.

Matching on Enums

type Color = enum(i32) {
    red
    green
    blue
}

fn color_name(c: Color) -> *u8 {
    return match c {
        .red:   "red",
        .green: "green",
        .blue:  "blue"
    }
}

Matching on Integers

Integer match requires a _ default arm (exhaustiveness cannot be verified for large domains):

fn classify(x: i32) -> *u8 {
    return match x {
        0:  "zero",
        1:  "one",
        -1: "minus one",
        _:  "other"
    }
}

Matching on Booleans

Boolean match is exhaustive when both true and false are covered:

fn bool_label(b: bool) -> i32 {
    return match b {
        true:  1,
        false: 0
    }
}

Matching on Tagged Unions

type Shape = union(enum) {
    circle: struct { radius: f64 }
    rect:   struct {
        w: f64
        h: f64
    }
    point
}

fn area(s: Shape) -> f64 {
    return match s {
        .circle(c): c.radius * c.radius * 3.14159,
        .rect(r):   r.w * r.h,
        .point:     0.0
    }
}

# By-reference capture: c is *PayloadStruct
const desc := match shape {
    .circle(&c): c.radius,
    .rect(r):   r.w,
    .point:     0.0
}

Default / Wildcard Arm

Use _ as the last arm to match any remaining value. For enums, a _ after full coverage is a compile error. _ must always be last. 

match code {
    200: "ok",
    404: "not found",
    _:   "other"
}
Matching on error(...) values
match/switch on a fallible call's error result transparently unwrap the compiler-generated Ok/Failed tag — you match directly against your own error variant names. See Error Handling.

Switch Statement

switch is the statement-level counterpart to match. Arm bodies are statements (not expressions). There is no exhaustiveness requirement and no result type. 

mut result: i32 = 0
switch x {
    0: result = 10,
    1: result = 20,
    _: result = 99
}

Switch arms use the same pattern syntax as match: variant patterns (.name), literal patterns, and the default wildcard _.

Switch on Enum

switch color {
    .red:   printf("red\n"),
    .green: printf("green\n"),
    .blue:  printf("blue\n")
}

Switch on Tagged Union

switch shape {
    .circle(c): printf("circle r=%.1f\n", c.radius),
    .rect(r):   printf("rect %.1fx%.1f\n", r.w, r.h),
    .point:     printf("point\n")
}
Watch the trailing comma with return
A switch arm body ending in return expr followed by a comma can be misparsed — the comma looks like it separates switch arms, but return itself accepts comma-separated multi-return values, so .A: return 1, .B: return 2 may not parse the way it looks. Wrap arm bodies containing return in a block: .A: { return 1 }, .B: { return 2 }.
Switch vs Match
Use match when you need a result value (it's an expression). Use switch when you need to execute statements per arm. Only match checks exhaustiveness.
